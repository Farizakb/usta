# Software supply chain incidents, 2026-09-23 to 2026-10-23 (Python backend / AI engineers)

Method note: ~17 tool calls (web search + fetch). Several primary pages (thehackernews.com, thenewstack.io) returned 403 or no body; for those I rely on search-result summaries and flag them. Vendor blogs are self-reporting. Coverage in the window is concentrated in Oct 5-22; I found NOTHING dated Sep 23-Oct 4 (see Gaps).

## Which PyPI / AI-ML packages were compromised or malicious, and how?

### Takeaway
The dominant in-window event is the 2026-10-21 LiteLLM 1.107.0 compromise (PyPI wheels + official Docker images), a .pth-based credential stealer plus hourly remote code loader, reached via stolen GitHub CLI OAuth tokens that hijacked the release pipeline. Smaller in-window items: repeated pyyi/leakdeep malicious PyPI uploads (Oct 19-21) and a Tensorlake npm SDK compromise (Oct 8). A worm variant ("testmetest") is being tested and can republish to PyPI.

### Cited Findings
**LiteLLM 1.107.0 (2026-10-21)**
- Malicious litellm 1.107.0 (all seven wheels) appeared on PyPI at 11:39:51 UTC on Oct 21; Chainguard scanning flagged it at 11:55 (16 min later); PyPI later quarantined it. Safe version: 1.106.2 (1.107.0rc1/rc2 also clean). — [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026)
- Docker images for v1.107.0 carried the same payload: ghcr.io/berriai/litellm, litellm-database, litellm-non_root, docker.io/litellm/litellm; Chainguard also lists tags latest, main-latest, main-stable on docker.io/litellm/litellm as affected. SecurityWeek says Docker Hub tags were removed or repointed to clean artifacts. — [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026); [SecurityWeek](https://www.securityweek.com/litellm-compromised-in-fresh-supply-chain-attack/)
- Mechanism: the sdist pyproject.toml gained one build line (`data = "cook"`) so maturin copied a `cook/` folder into the wheel's purelib (site-packages root). `cook.pth` imports `cook.py`, so the payload runs on ANY Python start in that environment, even if litellm is never imported. The GitHub v1.107.0 tag and sdist lack the payload files (wheel-only trojan). — [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026)
- Payload: ~61 KB "privcollect" stealer harvesting SSH/GPG/TLS keys, shell history, browser passwords/cookies, AWS/Azure/GCP creds, k8s configs/tokens, CI/CD secrets (GitLab Runner, Jenkins, Vault, Terraform, Packer), configs of 15+ AI coding tools, env vars, IMDS data, and the LiteLLM proxy DB tables (LiteLLM_CredentialsTable, LiteLLM_ProxyModelTable) via DATABASE_URL. Exfil: AES-256-CBC + RSA-4096-wrapped key, tar.gz over plain HTTP to a look-alike domain. `sitecustomize.py` starts a detached daemon (Linux/macOS) that hourly reads a GitHub dead drop, re-runs the stealer and executes downloaded Python with no integrity check. Windows: loader fails (needs os.fork) but stealer runs. The dead-drop file was empty during Chainguard's analysis (second stage not observed running). — [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026)
- Initial access (per SecurityWeek, citing LiteLLM's investigation): attackers obtained GitHub CLI OAuth tokens tied to an "innocuously named" account in an internal deployment exposed to the internet; LiteLLM suspects Claude Code embedded the tokens in response bodies that were logged to LiteLLM logs, which the attackers retrieved. With three developers' gh credentials they disabled branch protections, merged a change redirecting the releaser to a different source repository, ran a compromised workflow pointing at a lookalike repo, then signed and published the poisoned artifacts. How they reached the deployment/moved laterally is unclear. Chainguard says the initial access path was not publicly explained and is NOT linked to TeamPCP/the March incident. — [SecurityWeek](https://www.securityweek.com/litellm-compromised-in-fresh-supply-chain-attack/); [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026)
- Exposure window ~3 hours; est. >49,000 downloads of the malicious PyPI version (SecurityWeek); Wiz observed attackers abusing stolen credentials ~4.5 h after exfil, including querying Amazon Bedrock with stolen AWS creds. Enterprise customers pulling from LiteLLM's private repo reportedly unaffected. — [SecurityWeek](https://www.securityweek.com/litellm-compromised-in-fresh-supply-chain-attack/)
- Scale context: >100M PyPI downloads/month, >2,000 dependent packages (Chainguard). Wiz also reports GitHub took down the dead-drop repo. — [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026)
- IOCs: domain `www.litellm[.]dev` (/healthcheck exfil; NOT litellm.ai); dead drop `raw.githubusercontent[.]com/letters9813/pythonclient-test/main/domain.txt`; second stage `http://{domain}/codepy`; header `X-Token: XWiA8gZNa7NcX2XRoAEb`; files `cook.pth`, `cook.py`, `sitecustomize.py` in site-packages root; markers `/tmp/.pc_once_72129118c59f5636c0bb`, `/tmp/remote_code_loader.lock`, `/tmp/.pc_sq_*`, `/tmp/.pc_e_*`; env `PRIVCOLLECT_ACTIVE=1`. Example wheel SHA256 manylinux_2_28_x86_64: 462d0c9f67ca522d9e0e4acd245e90b36ce0d5353604a66bb7c43a1ec4a6fcf7 (all 7 hashes and image digests in the Chainguard post). — [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026)
- Remediation (Chainguard): check lockfiles/image digests with shell tools only (do not run python/pip in suspect env); isolate; kill the detached loader then delete cook.pth/cook.py/sitecustomize.py (inspect first), __pycache__, /tmp markers; block egress to litellm.dev and dead drop; hunt for /codepy requests (= possible arbitrary code exec); rotate SSH/GPG/TLS keys, cloud+k8s creds, publish/SCM tokens, AI tool tokens, DATABASE_URL, LiteLLM master/virtual keys and all provider keys in the credentials table; rebuild from verified artifacts; pin `litellm==1.106.2` and pin images by digest; verify wheels not just source; consider release cooldown policies. SecurityWeek/Aikido: removing the package does not undo damage, assume creds exposed. — [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026); [SecurityWeek](https://www.securityweek.com/litellm-compromised-in-fresh-supply-chain-attack/)
- Other write-ups exist (Wiz, Datadog Security Labs, StepSecurity, Rescana) but I did not fetch them: [Wiz](https://www.wiz.io/blog/litellm-compromised-steals-credentials), [Datadog](https://securitylabs.datadoghq.com/articles/litellm-compromised-pypi-docker/), [StepSecurity](https://www.stepsecurity.io/blog/litellm-1-107-0-compromised-pypi-backdoored-wheels-credential-stealer)
- Background (2026-03): TeamPCP reportedly published litellm 1.82.7/1.82.8 using a stolen PyPI token (first compromise). — [Chainguard](https://www.chainguard.dev/unchained/litellm-attacked-again-malicious-1-107-0-wheels-on-pypi-and-docker-hub-october-2026)

**Tensorlake (npm SDK for an AI agent infra vendor), 2026-10-08**
- tensorlake@0.5.144 on npm published Oct 8 01:12:07 UTC, flagged by Socket 11 min later; ChainDrop/Shai-Hulud family (linked to August keyv/cacheable compromises). Checkmarx: attacker used a compromised repo admin account to push to main of tensorlakeai/tensorlake; npm removed it ~3 h later; clean 0.5.145. Socket does not say a PyPI package was affected; I found no evidence of a PyPI tensorlake compromise. — [Socket](https://www.socket.dev/blog/tensorlake-compromise); [Checkmarx](https://checkmarx.com/zero-post/mini-shai-hulud-in-tensorlake-a-token-monitor-that-can-wipe-your-home-directory.md) (via search summary)
- Mechanism: `preinstall: node lib/setup.mjs` -> Bun-run obfuscated payload `lib/Math_Symbol.js`; no hardcoded C2 (resolves via Ethereum contract over ~30 public RPCs, GitHub fallback); self-propagates by republishing via npm; "hostage token" persistence `gh-token-monitor` polls api.github.com/user and runs attacker handler (home-dir wipe) if the stolen GitHub token is revoked. Targets npm/GitHub/AWS/Vault/k8s creds, SSH keys, .env, wallets, AI tool configs (.claude, .cursor, .kiro, Windsurf, Zed). IOC SHA-256: setup.mjs 25a0735d0db7dc40e5d45ce42d9c106067e6a66e184d967cfecfab17c3bcb5ef; Math_Symbol.js b50a00900399ba99fb6ce1fc151519cb99d44320ef2a631f2237e1aea0ad6fec. — [Socket](https://www.socket.dev/blog/tensorlake-compromise)
- Remediation: block 0.5.144, treat hosts that ran install scripts as compromised, REMOVE persistence BEFORE revoking tokens (revoking while monitor runs can wipe home dir): Linux `systemctl --user disable --now gh-token-monitor.service` + rm `~/.config/gh-token-monitor/`; macOS unload `~/Library/LaunchAgents/com.user.gh-token-monitor.plist`; Windows delete ONLOGON task running monitor.ps1; then rotate. — [Socket](https://www.socket.dev/blog/tensorlake-compromise)

**"testmetest" Miasma-variant worm test (Oct 12 / 19-22)**
- 15 npm packages named *testmetest from accounts `alexjoipamiba` and `testnewtestme`, Oct 19-22 (11 removed Oct 21, 4 live at Oct 22); `testmgkregme` removed Oct 12. Malicious: event-bus-lite-testmetest@0.0.1. SafeDep: only operator-owned test accounts seen, no third-party victims yet. Runs via `binding.gyp` (node-gyp rebuild), not install scripts; tries to disable StepSecurity Harden-Runner in GitHub Actions; steals SSH/npm/PyPI/Git creds, .env, AI tool keys, cloud/k8s secrets, Actions secrets from runner memory; exfil via commits to public repos on victim's GitHub and `aiarmor[.]website`; republishes to npm, PyPI, RubyGems, JFrog; `net-health-checker` service polls stolen token every 45 s for 48 h and deletes home dir on 401/403; `pkg-runtime` runs `sync.py` hourly (Python component; polls GitHub commits for C2). Drops AGENTS.md, .github/init.ps1, .claude/index.js. SafeDep has not confirmed lineage to Miasma (June 2026) / Mini Shai-Hulud. — [SafeDep](https://safedep.io/testmetest-npm-worm-miasma-variant/)

### Inferences
- LiteLLM is the second compromise of the same project in 2026 (March and Oct); the mechanism (wheel-only payload, .pth startup hook) means source-tag review and import-time sandboxing would not catch it. Hash/provenance checks must be on the installed wheel.
- Note the root cause per LiteLLM involves an AI coding tool leaking tokens into logs; relevant for AI engineers who log LLM/tool responses.
- The worm lineage (Mini Shai-Hulud/Miasma/Hades) is explicitly PyPI-capable (republishes to PyPI); the Oct 8 Tensorlake and Oct testmetest events show it is still being seeded.

### Gaps
- No in-window slopsquatting/AI-library typosquat campaign on PyPI found. Closest: OSSF MAL-2026-16135 "openaii" (.pth malware, dated Sep 11, OUTSIDE window) — [Vulners/OSSF](https://vulners.com/ossf/OSSF:MAL-2026-16135) (via search summary).
- No PyPI/PSF blog post for the LiteLLM incident or any in-window PyPI advisory found.
- Download count for LiteLLM varies (49k est. SecurityWeek vs. Chainguard's 100M/month is baseline traffic, not malicious downloads).
- Dead-drop second stage never observed active; actual attacker post-exploitation beyond Wiz's Bedrock observation unknown.

## CI/CD, container registry, IDE/extension compromises

### Takeaway
GhostAction (Oct 7-12+) injected credential-stealing GitHub Actions workflows via stolen maintainer PATs at large scale (hundreds to ~1,900 accounts, up to 30,000 repos depending on source). The LiteLLM release pipeline was itself hijacked and its Docker images poisoned. For IDE extensions I found only an undated Trivy VS Code extension compromise and Jul-Aug background; nothing dated in the window.

### Cited Findings
**GhostAction (GitHub Actions)**
- Socket reported >500 compromised GitHub accounts by Oct 9; later reports: ~1,900 hijacked accounts and >30,000 targeted repos (The New Stack headline; GitGuardian says >30,000 public repos hit Oct 8-12). Counts range 373-~1,900 accounts and 772->30,000 repos across sources (different windows/methods). Campaign first documented Sep 2025; this is an escalation starting ~Oct 7, 2026. — [The Hacker News](https://thehackernews.com/2026/10/credential-stealing-github-actions.html) (search summary; page 403 on fetch); [The New Stack](https://thenewstack.io/hackers-hijacked-1900-github-accounts-then-they-went-after-30000-repos/) (headline only); [InvisiRisk](https://www.invisirisk.com/blog/ghostaction-attack-targets-30000-github-repositories/) (search summary)
- Method: stolen PATs (from infostealer logs/credential dumps, per Aviatrix) used to push workflows disguised as security audits, `security-audit.yml` and `github_actions_security.yml`; exfiltrate repo secrets, env vars, git history over plain HTTP to 193.32.204[.]199. Not a GitHub Actions vulnerability. Stolen: AWS, Azure, PyPI and npm tokens, DockerHub, GitHub/GitLab tokens, SSH keys, DB creds, Anthropic and OpenAI API keys; >3,325 secrets (Aviatrix; other source says 2,577). — [Aviatrix](https://aviatrix.ai/threat-research-center/ghostaction-github-actions-credential-theft-2026/)
- Victims named: Takashi Kitao (pyxel) and Henry Wu (Uber athenadriver); PyPI link of pyxel is an inference, not stated. Reporters cited: THN, StepSecurity, Socket, GitGuardian. — [Aviatrix](https://aviatrix.ai/threat-research-center/ghostaction-github-actions-credential-theft-2026/)
- Remediation: rotate secrets immediately, search all repos for the two workflow file names and commits adding workflows that call the exfil IP, egress filtering/block plain HTTP, least-privilege PATs, monitor anomalous workflow changes. — [Aviatrix](https://aviatrix.ai/threat-research-center/ghostaction-github-actions-credential-theft-2026/)
- Discrepancy: Aviatrix FAQ says workflows added "since August 2026" vs. Sep 2025 start; treat start date as uncertain.

**Container images**
- LiteLLM official images poisoned Oct 21 (see above); image digests listed by Chainguard; advice: pin by digest.

**IDE / extensions**
- Trivy VS Code extension v1.8.12 on Open VSX contained code that abused a local AI coding agent to collect/exfiltrate secrets (CVE-2026-28353, GHSA-8mr6-gf9x-j8qg, CWE-506); removed; remove and rotate env secrets. Date NOT established; CVE number suggests earlier in 2026, so treat as background of unknown date. — [NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-28353) (via search summary)
- Background: 77 "evil twin" Open VSX extensions, active Jul 26-Aug 1 2026, removed by Aug 3 (Manifold); Open VSX stored XSS CVE-2026-13323 (fixed in 1.0.2); GlassWorm loader in four extensions Jan 30 2026. — [SC World](https://www.scworld.com/brief/77-malicious-extensions-found-on-open-vsx-marketplace); [Red Hat Bugzilla](https://bugzilla.redhat.com/show_bug.cgi?id=2495898)

### Inferences
- Both GhostAction and LiteLLM share the pattern: attacker holds a developer token (PAT / gh OAuth) and abuses CI/release workflows, so token hygiene and branch-protection/workflow-change alerting matter more than package scanning.

### Gaps
- No in-window GitLab CI, container registry (beyond LiteLLM), VS Code Marketplace or Open VSX incident found.
- Trivy extension compromise date unresolved.
- GhostAction primary reports (THN, Socket, GitGuardian, StepSecurity) not read directly.

## Self-propagating worms and credential-stealing campaigns; what did PyPI/GitHub/vendors recommend?

### Takeaway
Worm activity continues (ChainDrop/Mini Shai-Hulud in Tensorlake Oct 8; testmetest Miasma variant Oct 19-22). Recommendations come from security vendors, not PyPI/PSF/GitHub: I found no in-window PyPI blog or GitHub statement.

### Cited Findings
- ChainDrop/Shai-Hulud: keyv maintainer compromised Aug 4 2026; Microsoft confirms >400 packages, Aikido counted >=444 packages / >1,300 versions (counts vary). — [Elastic](https://www.elastic.co/security-labs/threat-command/shai-hulud-chaindrop-npm-supply-chain); [Aikido](https://www.aikido.dev/blog/keyv-and-friends-compromised-in-npm-supply-chain-attack) (Aug; BACKGROUND)
- Secondary claim (single blog summary, unverified): npm v12 disabled dependency install scripts by default on Jul 8 2026, yet payloads now run on import or via binding.gyp (testmetest), and some releases had valid provenance. — [brco.dev](https://brco.dev/insights/updates/npm-supply-chain-attacks-2026/) (search summary)
- Background (June 2026): Mini Shai-Hulud/Miasma/Hades PyPI waves: 37 malicious wheels across 19 packages (Orca says 26) using `*-setup.pth` startup hook, then 23 more artifacts with trojanized .abi3.so; typosquats rsquests/tlask/rlask; fake instructions aimed at AI scanners. — [Socket](https://socket.dev/blog/mini-shai-hulud-miasma-and-hades-worms-target-bioinformatics-and-mcp-developers-via-malicious); [Cyberpress](https://cyberpress.org/shai-hulud-attack-compromises-23-pypi-packages/)
- Background (May-Jul 2026): phishing proxy of PyPI login captured TOTP and pushed two malicious num2words releases; PyPI shipped a phishing-domain detector Jul 28 and revoked tokens (single search-summary source; unverified). Tenable: Mini Shai-Hulud (TeamPCP) >170 npm/PyPI packages, CVE-2026-45321. — [Tenable](https://www.tenable.com/blog/mini-shai-hulud-frequently-asked-questions)
- Common vendor advice across sources: assume compromise and rotate credentials after removing persistence; pin by digest/hash; release cooldowns; egress filtering; audit workflow changes (Chainguard, Socket, Aviatrix, SafeDep above).

### Inferences
- Worm "hostage token" wipers (Tensorlake, testmetest) change incident response order: remove persistence first, then revoke.

### Gaps
- No PyPI/PSF/GitHub statements in window located (blog.pypi.org search returned only 2025 posts and the older phishing items).
- Sep 23-Oct 4: no incidents found; could be genuine quiet period or search index gap.
